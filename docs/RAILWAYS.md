# 城市铁路与站场精细化

本轮把南宁站、南宁东站内的轨道与城区铁路统一建模，覆盖 `data/region.json` 定义的范围。铁路拥有独立的“铁路轨道”图层，包含钢轨、道床、轨枕、路基、铁路桥和接触网构件；车站建筑与站台仍属于建筑图层。

## 地理依据

`data/railways-source.json` 保存 Overpass 查询、接口、完整返回数据与 `2026-09-10T17:01:36Z` 的 OSM 时间戳。来源为 © OpenStreetMap contributors，许可 ODbL 1.0。仅使用 `railway=rail`，不把地铁、轻轨、规划线或废弃线补成现役铁路。

当前快照包含 **1,147 个铁路 way**，裁剪后股道几何合计约 **685.354 km**。此数累加并行股道、站场和联络线，**不是城市铁路线路里程**。其中 247 个 way 有桥梁标签，35 个有隧道标签；这些是数据分段数量，不代表独立桥梁或隧道数量。

投影沿用全城坐标，每单位 100 m。保留原始折线和节点编号，仅在城区边界裁剪并增补沿线高程采样点。不同高程的线路在平面上交叉时，不会仅因坐标相近而错误连接。两站已有快照中的 85 个铁路 way 与新快照几何一致；站台、站房和雨棚位置保持原有数据依据。

标签解释依据 [OSM railway](https://wiki.openstreetmap.org/wiki/Key:railway) 与 [electrified](https://wiki.openstreetmap.org/wiki/Key:electrified)：桥梁段生成桥面和支承，隧道段不绘制地表道床，只有地上与地下线路的连接口生成洞口框架；`electrified=contact_line` 段才添加架空接触网。三岸邕江特大桥的两个 way 有 `bridge:structure=truss` 标签，增加了开放钢桁架轮廓。

## 几何与高程

- 全线统一双钢轨，采用 1.435 m 的轨距；轨头显示宽度为 0.28 m，以保证沙盘近景可见。钢轨使用浅色连续轨面，配深灰绿色道床和浅色轨枕，省略竖向侧面。
- 道床包含顶面和斜肩，地面段补充坡脚接地的路基，桥梁段保留桥下空间、桥面边缘和桥墩。桥墩候选位置避开已知道路与不同层级的铁路；接触网柱避开相邻股道和道路。
- 用原始节点图统一连接处的高程。模型显示坡度上限为 0.12；这是经过全城高度夸张后的显示约束，不能作为真实铁路纵断面使用。
- 两站的既有轨面高度作为固定约束。东站西侧粗分辨率 DEM 与进站轨道冲突处，对展示地形作局部挖方和渐变过渡，原始高程数据不改动。道路、建筑、树木与森林表面使用同一修正。
- 采样包含地形网格及三角形对角线交点，检查精细、流畅两档地形，防止山坡在相邻采样点之间穿出轨道。
- 铁路走廊排除 114 栋程序化补充建筑，并在单树与林冠生成时留出通道；保留真实 OSM 建筑。

桥梁具体高度、跨径、桥墩样式、洞口外观与接触网位置没有工程测量依据，均为沿公开线路生成的沙盘示意。轨枕的显示间距约为精细档 8 m、流畅档 20 m，用于控制全城重复构件的数量，并不表示真实轨枕间距。未加入列车动画、信号系统或虚构的铁路运营信息。

## 两档模型

线路、钢轨、道床、路基、桥梁主体与洞口位置在两档中保持一致。参照清厢快速路的稀疏路灯，精细档保留候选接触网柱的一半，流畅档省略接触网柱，两档均省略细接触线。轨枕采用平面条纹，沿线方向宽度为 0.6 m，流畅档进一步降低轨枕密度。空间分块允许近景剔除画面外铁路；采用与清厢快速路相同的 0.4 m 边界采样误差和 60 m 最大分段长度，自适应合并多余网格。分岔和站场边界保留，坡度受统一约束，简化后的实际网格重新校验坡度与地形净空；轨枕和支柱贴合该网格。铁路构件的 Draco 位置量化使用 18 位，其余城市网格保持 14 位，避免细钢轨在大范围分块中压缩塌陷。

导出器适配项目使用的 Blender 5.2.1，临时设置铁路节点的压缩参数，导出后恢复 Blender 编码器；不修改 Blender 安装文件。

完整源文件为 `blender/nanning-city.blend`，两档模型位于 `public/models/`。网页不额外下载原始铁路数据，运行时只加载同站点的 GLB 与地图元数据。

## 重建与检查

```sh
work/venv/bin/pip install -r scripts/requirements.txt
work/venv/bin/python scripts/fetch_railways.py
work/venv/bin/python scripts/prepare_railways.py
work/venv/bin/python scripts/prepare_forest_canopy.py --stage all
npm run models:build
work/venv/bin/python scripts/validate_assets.py
```

下载脚本默认复用已有快照，只有显式 `--refresh` 才重新获取。全量重建应先完成地理数据、站场计划和高架计划，再准备铁路与林冠计划。各计划记录输入哈希，防止把旧铁路、旧林冠与新模型混用。

`scripts/validate_railways.py` 核对全部源折线覆盖、站场股道与外线连通性、来源哈希、图层归属，并解码两档 GLB 的钢轨检查数值和压缩后退化面。Blender 构建阶段检查两档地形净空、坡度及站场高程，并将结果写入地图元数据。

## 当前模型开销

| 内容 | 精细档 | 流畅档 |
| --- | ---: | ---: |
| 完整城市 GLB | 13,088,288 字节 | 9,723,364 字节 |
| 完整城市三角面 | 1,808,512 | 1,326,805 |
| 铁路主体三角面 | 350,992 | 350,992 |
| 铁路细节三角面 | 225,546 | 66,574 |

重复轨枕与接触网支柱不参与网页阴影投射，铁路桥梁、道床和路基仍保留阴影。模型面积统计不是性能测试；手机真机性能尚需实际设备确认。

相较上一版适度精简模型（13.24 / 10.09 MB），精细档体积减少约 1.1%，流畅档减少约 3.7%。本轮重点是与清厢快速路统一展示尺度和辨识度，非铁路网格的三角面数量保持一致。

## 本轮验证

- `scripts/validate_assets.py` 全量通过，包含两站与外线连通性、源线路覆盖、两档地形净空、林冠覆盖和 GLB 解码检查。两档压缩后钢轨距源节点最大平面距离均为 0.595 m（包含半轨距），74,836 个钢轨面中有 5 个微小退化面；最长钢轨平面边为 60.024 m，处于含压缩误差的 60.2 m 限值内。
- Python 语法检查和 `npm run build:pages` 通过，完整模型体积预算收紧为精细档 14 MB、流畅档 10.5 MB；铁路三角面预算收紧为 65 万和 50 万。
- 本地浏览器使用发布构建检查南宁站、南宁东站的站场与进出站股道，两档画质均能加载，东站近景保留可辨认的钢轨与站台。
