# P5 林冠连续净空与南湖采样修复

2026-09-13。P5 仍在实施中；本轮未更新正式地理、地形、两档 GLB 或 `.blend`。完整阶段要求继续遵循 [执行计划](URBAN_STRUCTURE_PLAN.md)。

## 问题与修复

原林冠验证器只检查三角面中心及三个边中点。新增 `scripts/check_canopy_clearance.py`，计算林冠与原生地形每个投影交集的所有顶点；两者高差在交集上是线性函数，因此能检查整个正面积交集的最小净空。另以交集并集检查支承覆盖，避免重叠面积掩盖缺口。

首次沿用 `validate_assets.py::raw_ground` 捕获几何，发现它遗漏主生成器中的南湖岸边、会展中心和体育中心修正，不能代替实际城市高度流程。该批 `canopy-coplanar-native` 结果仅保留为诊断，不作为实际城市几何验收。正式捕获工具改为执行主生成器初始化和完整高度流程，验证接路计划，再通过实际 Blender `Batch` 获取 float32 三角面。

实际近城区林冠仍有精细 8 面、流畅 43 面低于 9.5 m 净空。已列出的失败位置都位于南湖精细补片内；单独重切后最小净空未改善，失败面因细分增至 23 / 256，故该重切不能独立接入。

原因是 `terrain_mesh.py` 已使用 `build_park_terrain` 替换南湖粗网格，但 `forest_canopy.terrain_surface` 尚未采样这套三角面。新增 `blender/nanhu_terrain.py`，复用补片足印、三角方向和主生成器地面回调；共享采样器现在读取该表面。道路/地形来源清单已加入相关代码与数据，整套依赖仍须重新生成。

在保留 staging 文件的独立进程中，以新采样函数替换旧函数进行候选验证：精细失败消除，流畅剩余一面追加局部重切后消除。这是候选函数与实际 Blender 网格验证，尚非完整生产重建。

## 全域林冠导出修复与四组复验（2026-09-13）

对上一批三组失败继续做未压缩 GLB 对照，丢面和法线偏差仍然出现，因此不属于 Draco 位置精度问题。进一步只关闭法线量化也未解决，两个失败试验均保留。

逐面检查证明，上一批 all/detail 和 all/smooth 丢失的 2 / 4 个面均有坐标、材料及绕序相同的副本，且不是零面积面。Blender glTF 在压缩前调用网格验证，清除了这些重复面；不能以“退化面清理”为由删去有面积的独立表面。边界共点处理现跳过当前三角形已拥有的角点，避免在极薄三角形上把自身角点再次插到对边；此外，仅清除新生成且 3D 坐标、材料、绕序完全相同的副本，保留其覆盖表面。第三批四组分别清除 1 / 0 / 12 / 4 个新重复面，平面覆盖差仍与上一批相同，均小于既有 0.01 m² 上限。

法线偏差另有原因：Blender 在极薄面上可能返回长度很短的非零角点法线，glTF 提取器先舍入分量、再归一化，部分方向因此变为零并被替换为向上方向。导出器现仅在林冠法线提取期间保留分量精度，由其既有流程归一化；其他网格沿用原逻辑。成功及强制异常两种路径均验证法线方法、舍入设置和 Draco 方法恢复，没有修改安装目录。
