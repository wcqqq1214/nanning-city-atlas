# 连续城区模型范围

2026-10-12，用户确认以连续主城区为重点，随后明确要求外观保持长方形，线外参考 gxu-campus-3d 的校外处理。当前发布模型为完整长方形底座：城区保留建筑、地标和城市内部山水；城区线只控制精度，不产生岛状外沿或内侧断崖。园博园后续单独加入。

城区外约 1 km 的衔接区保留校准过的原地形及出城道路、铁路；与城区相连的主要水体及两岸 300 m 也保留原网格，让邕江等水系连续穿过衔接区。山林向外延续，林冠起伏在 1.8 km 内逐渐贴合外围地形，天然林地底色继续覆盖远处山体。更外侧的长方形四角采用 200 m 网格低模地形、水系和贴地的主路示意，不恢复乡村建筑、密集单体树、路灯或铁路细部。

前端沿用 GXU 的淡色外围处理思路，在同一张纹理内记录城区细节权重与实际林地范围。地面、林冠、道路和水系的颜色随距离逐渐减弱，林地远景保持灰绿色，避免沿城区线出现绿色山林与裸地的硬切边。地形与水体始终不透明；几何接缝实际相接。

这是产品展示范围，不是南宁行政边界、官方建成区边界或地籍线。

## 范围与数据覆盖

- [控制点](../../data/urban-core-boundary-source.json)：用户已认可的展示范围，六段 WGS84 控制线保留各自依据和不确定性。园博园不进入本次精细范围。
- [派生 GeoJSON](../../data/urban-core-boundary.geojson)：`core` / `context` 表达完整设计范围；真正用于导出的角色是 `export-core`（精细城区）、`export-transition`（原地形、江岸与交通衔接区）、`export-landscape`（林冠渐退范围）、`export-context`（完整长方形外框），都限制在现有数据覆盖内。
- [范围生成器](../../scripts/urban_scope.py)：对 70 个跨线建筑保留完整轮廓，并在靠线的保留建筑周围增加 20 m 场地余量。不会迭代吸收远处乡村街区。
- [空间检查](../../scripts/prepare_urban_core_boundary.py)：检查闭环、有效性、37 个探索点及 8 处已标注校园、公园范围。

## 几何处理与导出

[scripts/scope_city.py](../../scripts/scope_city.py) 读取完成的全量 GLB，在导出阶段收边，保留已有地形整平、桥梁、场地和地标校准。全量地理输入及其散列依赖保持原状。

- 完全在线内的 Draco primitive 直接复制压缩字节。33 个精细地标模型全部原样保留。
- 跨线道路、水面、地形和林冠按原三角面的平面插值裁切，保留绕序并插值法线。竖直护坡也单独处理，不能只判断二维面积或中心点。
- 建筑和单体树按连通组件完整保留或移除。源数据跨线建筑先通过范围避让保护，不切成半栋。
- 与城区相连、面积至少 0.5 km² 的水体保留到长方形外框，其两岸 300 m 并入原地形衔接区。细节线不会把邕江变成被粗网格遮挡的断头河。现有源模型中个别小水塘的水位与地形问题不在此规则内。
- 城区内林冠位置保持原样；线外林冠以 smoothstep 衰减高度；发生面内穿地的三角面按实际地形交集细分，在相邻地形接缝取较高表面，并对不超过 10 cm 的量化残差做受限抬升。超过该范围会阻止导出。渐退终点贴地，避免抬高的林冠在末端又形成断壁。法线也随衰减过渡。远处林地颜色来自现有 `forest-plan.json`，不增加单体树。
- 底座只沿长方形外框生成侧壁和底面，侧壁高度跟随实际地形和水面；内部城区控制线不生成侧壁。
- [city_context.py](../../scripts/city_context.py) 从原 GLB 的地形面采样外围高程，以 200 m 网格生成背景。遇到源网格孔隙时取最近三角面上的最近点，禁止将狭窄护坡的平面向远处外推成尖刺。衔接边保留原裁切顶点和分段高度；水岸参与网格分割，地面仍覆盖水下区域，关闭水体图层不会露出空洞。主路投影到同一套新网格上。
- 简化背景的地形分别为 21,922 / 19,976 个三角面，主路为 5,638 / 5,338 个三角面（精细 / 轻量）。这是示意环境，非新增测绘精度。
- 改动的 primitive 重新压缩并逐面做一一匹配。道路、铁路、地形和水面新增位置误差上限 1 cm；建筑、树冠和底座为 5 cm；林冠位置无损。法线误差上限 0.5°。完全未改动的 primitive 不发生二次量化。
- 已经退化为零面积的源三角面在重编码时显式计数移除；新裁切产生的退化碎片不会进入结果。

前端全景按长方形四角取景，镜头中心移到新范围中部；平移范围和小地图都保持长方形，四角背景可正常浏览。

## 重建与验证

在已安装 [几何依赖](../../scripts/requirements.txt) 的 Python 环境中执行。重压缩调用本机 Blender 附带的 Draco 桥接库；默认资源路径为 `/Applications/Blender.app/Contents/Resources`，可用 `--blender-resources` 指定。网页运行与静态构建不需要 Blender。

```sh
# 只改范围时，使用已保存的全量资产，不必重新生成 Blender 场景。
source work/venv/bin/activate
npm run models:scope

# 全量建模输出到 work/full-city，随后自动裁切、验证并发布到 public。
npm run models:build

# 发布模型边界、固定体积预算、林冠面内净空、地标与散列检查；不需要本地全量基准。
python scripts/check_urban_scope_exports.py

# 有基准时，额外核对原样复制的压缩块和材质。
python scripts/check_urban_scope_exports.py --baseline work/full-city

# 全套已发布模型检查；源计划失配仍报错，但会跑完各项独立诊断。
python scripts/validate_runtime_assets.py

# 源地理输入 + 上述模型检查的完整入口。
python scripts/validate_assets.py
```

范围更改后，`prepare_urban_core_boundary.py` 会重新生成 GeoJSON。`scope_city.py` 默认写入 `work/urban-scope-review/latest-candidate`；只有 `--publish` 才在两档模型验证通过后替换发布资产。脚本拒绝把已裁切模型当作全量输入，防止重复裁切及统计基准漂移。

本次按依赖顺序重新生成森林、地面道路、高架、道路实体和竹溪细节计划，重新捕获原生高程，完成全量 Blender 建模、平面地形打包及城区导出。本地 `blender/nanning-city.blend` 已同步为最新可编辑全量场景，只保留这一份 Blender 文件。原始捕获、重建日志和复审报告位于 `work/urban-scope-review/hash-rebuild/`。运行时必需的建筑高度已迁入 `data/road-building-levels.json`，道路计划不再依赖被忽略的临时文件；本地全量中间 GLB 不随 Git 分发，新克隆需要完整建模环境才能重新导出，现有城区发布资产可以直接运行。

截至 2026-10-13，修复复审后的 17 项前端测试、286 项数据测试、类型检查、lint、静态构建、裁切专项检查和完整 `validate_assets.py` 均通过。专项检查覆盖长方形外框、外围地面面积、26 MB / 18 MB 固定下载上限、主要水系原网格连续性及内部不得生成侧壁的约束；两档地形接缝最大高度误差为 0.96 cm / 0.25 cm。林冠整面检查按与地形的交集顶点求净空极值，XY 容差为 2 mm、垂直容差为 2 cm；两档最小净空均约 5 mm，渐退末端最大离地为 0.94 cm / 0.80 cm。带全量基准的检查还确认林地覆盖没有丢失或填平空地（XY 容差 3 mm）。新增回归用例覆盖安全顶点下的面内山脊、外缘山谷贴合、接缝高程、固定预算、城区校验完整执行、紧凑地形面法线恢复和无临时目录的道路加载。

前轮浏览器检查覆盖山林前后对比、邕江西侧接入段和 390 px 手机布局。本次重新加载最终静态构建的两档模型，核对完整长方形全景，控制台没有警告或错误；33 个精细地标的压缩数据与本次全量基准一致。最终预览为 `work/urban-scope-review/hash-rebuild/final-city-overview.png` 和 `final-smooth-overview.png`。未进行真机性能测量。

## 依据与限制

控制线结合项目 2026-09-08 OSM 快照的用地、水体、主干路、林地和用户的市区地图截图人工拟定。截图仅帮助判断连续城区形态，没有按截图边框或像素直接生成地理边界。

[广西自然资源厅关于南宁城区范围试划的说明](https://dnr.gxzf.gov.cn/xwzx/gnzx/t18331259.shtml)只用于范围判断原则，未作为坐标来源。此前两次补充 Overpass 请求分别返回 HTTP 504 和读取超时，未取得新的完整东、南侧快照；这些延伸区域及园博园留待后续单独处理。
