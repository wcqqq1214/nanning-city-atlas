# 基础城市与近景按需加载

参考 GXU 的基础场景、前景优先队列和解码内存预算，城市主页先载入连续地形、水体、普通建筑体块及地标主体；靠近或选中地点后，补充地标装饰、道路标线和铁路细部。城市使用每单位 100 米的坐标，加载距离已换算，不能直接照搬校园的米制参数。

## 资产及保真约束

`npm run models:stream` 从两档完整正式 GLB 生成 `public/models/stream/{detail,smooth}/` 和 `public/data/city-streaming.json`，每档包含基础模型和 44 个细节区块。`models:scope` 在发布城区模型后自动调用此步骤。

| 档位 | 完整模型 | 首次基础模型 | 减少 |
| --- | ---: | ---: | ---: |
| 精细 | 24,308,092 bytes | 19,736,616 bytes | 18.8% |
| 流畅 | 16,867,248 bytes | 14,210,700 bytes | 15.7% |

原始完整 GLB 保留给检查页面和几何验收。因此降低的是主页首次模型下载量，仓库及静态发布包总量会增加。普通建筑体块仍常驻，不能把此实现描述成所有建筑均分区加载。

生成器只复制完整压缩图元，不重新编码、不删面、不重新裁切山水。校验器逐图元比较压缩内容散列、材质和节点层级，并核对基础与细节的并集恰好等于源模型。地形、水面、底座、普通建筑及每个地标主体必须留在基础包。静态发布另行核对所有区块的字节数和 SHA-256。

## 调度和资源

- 镜头目标距离小于 70 单位时加载附近细节，搜索半径为 6–40 单位；选中地标始终优先。隐藏图层不会占用对应的细节预算。
- 最多两个并发请求；离开区域或销毁场景会取消不再需要的请求。JSON 超时 15 秒，模型超时 45 秒，包含响应正文；临时失败最多三次，404 等永久错误不自动重复。
- 近景预算按解码后几何及灯光缓冲区计算。普通桌面三级预算为 64/48/24 MiB，窄屏上限 32 MiB。这不是整个浏览器或 GPU 的总内存上限；基础城市与同时解码的临时缓冲区不在此指标内。
- 远离后释放几何、材质、纹理及解码位图，保护仍被场景共享的资源。下载完成但已失去用途的模型也立即释放。
- 近景失败保留基础城市，显示独立的重试入口。

现有道路已按区域合批。额外运行时合批的兼容性清点显示，全部细节最多减少精细 3、流畅 2 个网格，收益不足以保留额外遍历与合并逻辑。树木已有低面数分区几何；本轮保留它们，未宣称实现树木实例化或动态密度。

## 画质与分享

自动画质根据前台活动样本调整像素比例、阴影与近景预算；连续低帧率降档，恢复需更多稳定样本和冷却时间。后台、静止帧不触发降档。流畅档按约 30 fps 节拍绘制，静止时休息。手动精细优先于自动降档。

手动画质切换会重新加载相应基础模型，同时保存当前镜头和环境；自动调档在当前场景内进行。分享链接保留选中地标、镜头、时间、高度、图层和俯视状态，并用可见半跨度适应不同屏幕。外来链接先校验数值、地图范围与地标 ID。分享不会自动开启环绕。

主页 `?stats` 诊断面板显示基础下载量、绘制调用、近景区块数及近景几何 MiB。帧率单次读数只能说明当时表现；跨版本提升需要相同设备、镜头、画质与重复测量，不能从文件缩小比例推算。
